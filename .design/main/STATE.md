- **Extending the six-kind analytics `stat_events`/`stat_dailies` model to a new kind is a real migration, not a code-only enum change** — both tables' `kind` CHECK constraints must be widened by name (`{table}_kind_check`; `stat_events` stays partitioned, so the parent-table `ALTER` propagates to partitions automatically), and `AnalyticsRollupJob`'s `selectRaw`/`groupBy`/insert plus `stat_dailies_unique_rollup`'s column list are hand-enumerated, not generic — a new dimension column added to `stat_events` silently never rolls up until this job is also touched (confirmed by `T-6D04`'s `api_request` kind and its new `endpoint` column).

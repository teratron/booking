# Обзор — что это и какую инструкцию выбрать

Прочитайте эту страницу один раз, прежде чем выбирать инструкцию. Здесь
простым языком описано, из чего состоит проект и для чего нужна каждая из
четырёх инструкций по установке.

## Что это за проект

**Международный туристический портал-справочник** для Молдовы, Украины и
Грузии. Он публикует туристические объекты (места проживания, что
посмотреть) и направляет посетителя напрямую на телефон или мессенджер
владельца. Это **не система бронирования** — никаких броней и никаких
платежей между посетителем и владельцем. Доход приносит **платное
размещение**: владельцы объектов платят за то, чтобы быть в справочнике и
занимать позицию выше.

У портала три «лица»:

- **Публичный сайт** — то, что видит посетитель. Каждая страница находится
  под двухбуквенным языковым префиксом, например `/en/...` (английский) или
  `/ru/...` (русский). Открытие сайта по «голому» адресу перенаправляет на
  один из них.
- **Панель персонала** — где ваша команда модерирует объекты, ведёт
  владельцев, продаёт размещение, редактирует контент. Находится по нарочито
  неочевидному адресу (`/portal-admin` по умолчанию, меняется), никогда по
  `/admin`.
- **Кабинет владельца** — где владелец объекта управляет своими
  объявлениями. По умолчанию `/cabinet`.

## Из чего он состоит

Понимать это, чтобы следовать инструкции, не обязательно, но эти слова
встречаются в каждой инструкции — вот чем занимается каждая часть:

| Часть | Что делает, простыми словами |
| --- | --- |
| **Приложение** | Сам сайт. Написан на PHP на фреймворке Laravel. |
| **PostgreSQL** (с PostGIS) | База данных — постоянное хранилище всех объектов, владельцев, территорий, оплаченного размещения и т. д. PostGIS — дополнение, отвечающее на вопрос «что находится рядом с этой точкой на карте». |
| **Redis** | Быстрая временная память для кеша, сессий входа и очереди фоновой работы. |
| **Объектное хранилище** (S3-совместимое) | Где лежат загруженные фото и файлы. На вашем компьютере это небольшая программа **MinIO**; в продакшене — облачный bucket (Cloudflare R2 или Backblaze B2). |
| **Обработчик очереди** (Horizon) | Фоновый процесс, выполняющий медленную работу незаметно — отправку писем-уведомлений, обработку импортов, построение месячной статистики. |
| **Планировщик** | Фоновый процесс, запускающий задачи по расписанию — ночной бэкап базы, снятие с публикации завершившегося размещения, перегенерацию карты сайта. |
| **Pulse** | Фоновый процесс плюс дашборд, показывающий, как работает сайт. |
| **Почта** | Исходящая почта. На вашем компьютере ловушка **Mailpit** показывает письма, не отправляя их; в продакшене письма отправляет настоящий почтовый релей. |
| **Отслеживание ошибок** (Sentry) | Необязательно. Собирает отчёты о сбоях. Выключено, пока не укажете адрес. |

С **Docker** всё это запускается вместе одной командой, и вы ничего не
устанавливаете сами. Без Docker вы устанавливаете и запускаете каждую часть
вручную.

## Четыре инструкции — выберите одну

Вопроса два: **где** это работает и **как** установлены части.

| | **С Docker** (рекомендуется) | **Без Docker** |
| --- | --- | --- |
| **На вашем компьютере** (посмотреть или разрабатывать) | [`local-with-docker.md`](local-with-docker.md) | [`local-without-docker.md`](local-without-docker.md) |
| **На настоящем сервере** (живой сайт для посетителей) | [`production-with-docker.md`](production-with-docker.md) | [`production-without-docker.md`](production-without-docker.md) |

**Рекомендация:** используйте Docker в обоих случаях. Проект спроектирован и
протестирован вокруг него — процесс релиза, автоматическая проверка
работоспособности и откат одной командой рассчитаны на Docker-настройку
продакшена. Инструкции «без Docker» существуют на случай, когда Docker
действительно нельзя использовать; они требуют больше работы и дают меньше
подстраховки.

После любой инструкции перейдите к
[`first-run-and-daily-tasks.md`](first-run-and-daily-tasks.md), чтобы
убедиться, что всё заработало, и войти в первый раз. Если шаг ведёт себя не
так, см. [`troubleshooting.md`](troubleshooting.md).

## Несколько фактов, на которые опирается каждая инструкция

- Коду нужны **PHP 8.5**, **PostgreSQL 18**, **Redis 8**, **Node.js 24** и
  **pnpm** (менеджер пакетов для стилей и скриптов сайта). Docker приносит
  нужные версии; без Docker вы устанавливаете их сами.
- Приложение проверяет собственную работоспособность по адресу **`/up`**.
  Простой `200 OK` там означает, что оно запустилось корректно.
- Вложенный пример файла настроек, `.env.example`, уже подходит для
  инструкции **локально с Docker** без правок. Любой другой инструкции нужны
  правки, и она их подробно описывает.
- Свежая локальная установка создаёт стартовую учётную запись администратора:
  `test@example.com` с паролем `password`. Она только для локального
  использования — никогда не переносите её на настоящий сервер. См.
  [`first-run-and-daily-tasks.md`](first-run-and-daily-tasks.md).

## Словарь

- **Терминал** / **командная строка** — текстовое окно, куда вы вводите
  команды из этих инструкций. В Windows это *PowerShell* или *Windows
  Terminal*; в macOS и Linux — *Terminal*.
- **Репозиторий** / **repo** — папка проекта с кодом, отслеживаемая
  инструментом *Git*.
- **Файл `.env`** — обычный текстовый файл с настройками (адреса, пароли,
  переключатели), который приложение читает при запуске. Он никогда не
  публикуется и не попадает в Git.
- **Контейнер** — одна упакованная работающая часть (приложение, база данных,
  …) под управлением Docker. «Поднять стек» означает «запустить все
  контейнеры».
- **Миграция** — одно упорядоченное изменение структуры базы данных.
  «Выполнить миграции» означает «привести структуру базы в соответствие с
  кодом».
- **Наполнение** (seeding) — заполнение свежей базы стартовыми данными, без
  которых сайт вообще не работает: список языков, стран, уровней территорий,
  типов объектов, ролей, прав и т. д.
- **Собрать ассеты** — превратить исходные стили и скрипты сайта в компактные
  файлы, которые скачивает браузер. Делается командой `pnpm build`.
- **Ассеты панелей** — собственные стили и скрипты панели персонала и
  кабинета. Публикуются командой `php artisan filament:assets`. Если панели
  выглядят «сломанными» и без стилей — этот шаг пропущен.
- **Очередь** — список фоновых задач, ожидающих выполнения. Их обрабатывает
  Horizon.
- **Продакшен** — настоящий живой сайт на настоящем сервере, в отличие от
  копии на вашем компьютере.

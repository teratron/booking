# Запуск на вашем компьютере, с Docker

Это самый простой способ получить рабочую копию всего сайта на своей машине —
посмотреть, показать или разрабатывать. Docker устанавливает и запускает
каждую часть за вас (базу данных, Redis, хранилище, ловушку почты, фоновые
процессы); сами вы почти ничего не устанавливаете.

Сначала прочитайте [`overview.md`](overview.md), если ещё не читали.

## Что получится в итоге

- Публичный сайт по адресу **`http://localhost:8300/en`** (и `/ru`).
- Панель персонала по адресу **`http://localhost:8300/portal-admin`**.
- Кабинет владельца по адресу **`http://localhost:8300/cabinet`**.
- Стартовый администратор, под которым можно войти.
- Вспомогательные инструменты: ловушка почты `http://localhost:8325`,
  консоль файлового хранилища `http://localhost:9101`, дашборд очереди
  `http://localhost:8300/horizon`.

## Перед началом

Установите две вещи. Больше ничего.

- **Docker Desktop** (Windows или macOS) или **Docker Engine + плагин
  Compose** (Linux). После установки откройте его один раз и дождитесь
  статуса «запущен». Проверка из терминала:

  ```
  docker --version
  docker compose version
  ```

  Обе команды должны напечатать номер версии.

- **Git**, чтобы скачать код:

  ```
  git --version
  ```

- Около **6 ГБ** свободного места на диске и рабочий интернет для первого
  запуска (части скачиваются один раз).

PHP, PostgreSQL, Redis и Node.js на вашей машине для этой инструкции **не
нужны**.

## Шаги

### 1. Получите код

Выберите папку для проектов, откройте в ней терминал и выполните:

```
git clone <адрес репозитория> booking
cd booking
```

Спросите у разработчика точный адрес репозитория, если его у вас нет. Дальше
все команды выполняются **внутри этой папки `booking`**.

**Должно получиться:** папка `booking` с файлами `docker-compose.yml`,
`composer.json`, папкой `app/` и множеством других.

### 2. Создайте файл настроек

В проекте есть пример файла настроек. Скопируйте его под тем именем, которое
приложение действительно читает:

- macOS / Linux: `cp .env.example .env`
- Windows PowerShell: `Copy-Item .env.example .env`

**Не редактируйте его.** Для этой инструкции значения из примера уже
правильные.

**Должно получиться:** новый файл `.env` рядом с `.env.example`.

### 3. Запустите всё

```
docker compose up -d --build
```

Первый запуск занимает несколько минут — скачиваются и собираются части.
Последующие запуски — секунды. `-d` означает «в фоне»; `--build` означает
«собрать образ приложения с нуля», нужно только в первый раз и после
изменения Docker-рецепта приложения.

Это запускает:

| Часть | Где вы к ней обращаетесь |
| --- | --- |
| `nginx` — веб-вход | `http://localhost:8300` |
| `app` — приложение | (за nginx) |
| `postgres` — база данных | порт `5433` на вашей машине |
| `redis` — быстрая память | порт `6379` |
| `minio` — файловое хранилище | консоль `http://localhost:9101` |
| `mailpit` — ловушка почты | `http://localhost:8325` |
| `worker`, `scheduler`, `pulse` — фоновые процессы | (собственной страницы нет) |

**Должно получиться:** `docker compose ps` перечисляет все сервисы, и через
минуту строки `postgres` и `redis` показывают `healthy`.

> Если команда жалуется, что **порт уже занят**, значит, этот номер уже
> использует что-то другое на вашей машине. См.
> [`troubleshooting.md`](troubleshooting.md) → «Порт уже занят».

### 4. Установите части самого приложения

Docker запустил *сервисы*. Теперь настройте *приложение* внутри контейнера
`app`. Выполняйте по одной команде:

```
docker compose exec app composer install
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate --seed
docker compose exec app php artisan filament:assets
docker compose exec -e CI=true app pnpm install
docker compose exec app pnpm build
```

Что делает каждая:

1. `composer install` — скачать PHP-библиотеки, нужные коду.
2. `key:generate` — создать секрет, которым приложение шифрует cookie и
   сессии. Записывает его в `.env`.
3. `migrate --seed` — построить структуру базы, затем наполнить её стартовыми
   данными (языки, страны, уровни территорий, типы объектов, роли, права)
   **и** стартовым администратором (`test@example.com` / `password`).
4. `filament:assets` — опубликовать стили панели персонала и кабинета.
   Пропустите — обе панели отобразятся как текст без стилей.
5. `pnpm install` — скачать фронтенд-библиотеки. `-e CI=true` не даёт команде
   встать на подтверждении, которое здесь некому дать.
6. `pnpm build` — собрать стили и скрипты сайта.

**Должно получиться:** `migrate --seed` печатает список миграций, каждая
помечена `DONE`, затем `Database seeding completed successfully`.

### 5. Откройте сайт

Откройте **`http://localhost:8300`** в браузере. Он перенаправит на
`http://localhost:8300/en`.

**Должно получиться:** главная страница туристического портала с настоящим
наполненным контентом (названия территорий, карточки объектов), корректно
оформленная.

## Как понять, что всё заработало

Пройдите [`first-run-and-daily-tasks.md`](first-run-and-daily-tasks.md).
Коротко:

- `http://localhost:8300/up` показывает простой **`200`** / «OK».
- `http://localhost:8300/en` открывается и оформлен.
- `http://localhost:8300/portal-admin` показывает страницу входа.
- Там можно войти с `test@example.com` / `password` (после чего вас проведут
  через настройку второго фактора входа).

## Повседневное использование после первой настройки

Шаги 1–2 не повторяются. Шаг 4 повторяется редко (только после подтягивания
нового кода — см.
[`first-run-and-daily-tasks.md`](first-run-and-daily-tasks.md)). Обычная
работа:

| Задача | Команда |
| --- | --- |
| Запустить сайт (уже настроен) | `docker compose up -d` |
| Остановить, сохранив данные | `docker compose stop` |
| Остановить и удалить контейнеры (данные сохранятся) | `docker compose down` |
| Смотреть живой лог приложения | `docker compose logs -f app` |
| Открыть терминал внутри приложения | `docker compose exec app bash` |
| Живая пересборка стилей при разработке | `docker compose exec app pnpm dev` (оставить запущенным) |
| Стереть и пересоздать базу | `docker compose exec app php artisan migrate:fresh --seed` |

Данные лежат в томах Docker и переживают `stop` и `down`. Чтобы стереть их
полностью, добавьте `-v`: `docker compose down -v` (необратимо).

## Если что-то не работает

- **Порт уже занят** → [`troubleshooting.md`](troubleshooting.md).
- **Главная перенаправляет туда, что не открывается, или пропали стили** →
  вероятно, вы отредактировали `.env` на шаге 2, либо присутствует старый
  `.env`. Его `APP_URL` должен быть ровно `http://localhost:8300`.
  Исправьте, затем `docker compose exec app php artisan config:clear` и
  `docker compose exec app php artisan cache:clear`.
- **Панели выглядят как обычный текст** → шаг 4.4 (`filament:assets`)
  пропущен или не выполнился. Повторите его.
- **`pnpm install` встаёт и ждёт, потом падает** → запускайте с `-e CI=true`,
  как показано в шаге 4.
- **Каждая страница очень медленная** (много секунд) → это накладные расходы
  Docker на общий доступ к файлам в Windows и macOS, и для тяжёлой работы это
  ожидаемо. См. [`troubleshooting.md`](troubleshooting.md) → «Всё медленно
  под Docker».
- **Что-то ещё** → [`troubleshooting.md`](troubleshooting.md).

# Запуск на вашем компьютере, без Docker

Используйте это, только если не можете или не хотите использовать Docker.
Результат тот же, что и в [`local-with-docker.md`](local-with-docker.md), но
каждую часть вы устанавливаете и запускаете сами: PHP, PostgreSQL, Redis,
Node.js, файловое хранилище и фоновые процессы.

Это заметно больше работы и больше движущихся частей. Если Docker доступен,
используйте инструкцию с Docker.

Сначала прочитайте [`overview.md`](overview.md), если ещё не читали.

## Что получится в итоге

То же, что и с Docker — публичный сайт, панель персонала, кабинет владельца и
стартовый администратор — но доступное по тому веб-адресу, который **вы**
настроите (обычно `http://127.0.0.1:8000` от встроенного сервера, или домен
`.test`, если используете Laravel Herd).

## Перед началом — установите среды выполнения

Вам нужны следующие мажорные версии:

| Программа | Версия | Примечания |
| --- | --- | --- |
| **PHP** | 8.5 | С расширениями: `intl`, `pdo_pgsql`, `pgsql`, `redis`, `imagick`, `gd`, `zip`, `bcmath`, `exif`, `pcntl`, `opcache`. |
| **Composer** | 2.x | Менеджер пакетов PHP. |
| **PostgreSQL** | 18 | С **PostGIS**, а также доступными расширениями `pg_trgm` и `unaccent`. |
| **Redis** | 8 | |
| **Node.js** | 24 | |
| **pnpm** | 11.x | Установить `npm install -g pnpm` или включить `corepack enable`. |
| **postgresql-client** | 18 | Даёт `pg_dump`, используется задачей бэкапа. Совпадает по мажорной версии с сервером. |

Рекомендуемые упрощения:

- **Windows или macOS:** [Laravel Herd](https://herd.laravel.com) даёт PHP
  (несколько версий), nginx и домен `.test` из коробки. Herd Pro добавляет
  PostgreSQL и Redis. На этих системах это самый гладкий путь.
- **Linux:** установите пакеты из вашего дистрибутива или из известных
  репозиториев PHP и PostgreSQL.

Необязательно, чтобы приблизиться к опыту с Docker:

- **MinIO** (небольшой S3-совместимый сервер хранения) — или укажите
  хранилище на настоящий облачный bucket.
- **Mailpit** (локальная ловушка почты) — или пусть попытки отправки почты
  в разработке просто завершаются ошибкой.

Проверьте основные версии перед продолжением:

```
php -v          # должно показать 8.5.x
composer -V
psql --version  # должно показать 18.x
redis-cli --version
node -v          # должно показать v24.x
pnpm -v
```

> На некоторых конфигурациях Windows команда `php` указывает на более старую
> версию даже после установки 8.5. Если `php -v` не 8.5, вызывайте
> версионированный бинарник напрямую (например, `php85`) во всех командах
> ниже, либо сделайте 8.5 версией по умолчанию в вашем менеджере PHP. См.
> [`troubleshooting.md`](troubleshooting.md) → «`php -v` показывает не ту
> версию».

## Шаги

### 1. Создайте базы данных и расширения

Откройте административную оболочку PostgreSQL (`psql -U postgres`) и
выполните:

```
CREATE ROLE booking WITH LOGIN PASSWORD 'booking';
CREATE DATABASE booking OWNER booking;
CREATE DATABASE booking_testing OWNER booking;
\c booking
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;
\c booking_testing
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;
```

`booking_testing` используется только при запуске автоматических тестов;
создайте её сейчас, чтобы не возвращаться к этому шагу.

**Должно получиться:** `\l` перечисляет и `booking`, и `booking_testing`.

### 2. Получите код

```
git clone <адрес репозитория> booking
cd booking
```

Все команды ниже выполняются внутри этой папки.

### 3. Создайте и отредактируйте файл настроек

```
cp .env.example .env      # Windows: Copy-Item .env.example .env
```

Теперь **отредактируйте `.env`** в текстовом редакторе. Пример файла
рассчитан на Docker; нужно перенаправить его на ваши локальные установки:

| Настройка | Установите в | Зачем |
| --- | --- | --- |
| `APP_URL` | Точный адрес, который вы будете вводить в браузере, включая `http://` и порт — напр. `http://127.0.0.1:8000`, или `http://booking.test`, если используете домен Herd. | Сайт строит из этого свои ссылки и перенаправления. Неверное значение отправит вас на адрес, который не отвечает. |
| `DB_HOST` | `127.0.0.1` | Ваш локальный PostgreSQL. |
| `DB_PORT` | `5432` (обычный порт PostgreSQL) | В примере `5433` по Docker-специфичной причине, здесь она не применима. |
| `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` | `booking` / `booking` / `booking` (как в шаге 1) | |
| `REDIS_HOST` / `REDIS_PORT` | `127.0.0.1` / `6379` | Ваш локальный Redis. |
| `MAIL_HOST` / `MAIL_PORT` | `127.0.0.1` / `1025`, если запущен Mailpit; иначе оставьте как есть | |
| `AWS_ENDPOINT` | `http://127.0.0.1:9000`, если MinIO запущен локально; иначе endpoint вашего настоящего bucket | |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_BUCKET` | В соответствии с вашим MinIO или облачным bucket | |

Если вы запускаете MinIO локально, создайте также два нужных ему bucket
(`booking-media` и `booking-backups`) из консоли или клиентом `mc`.

**Должно получиться:** `.env` теперь указывает каждый адрес на `127.0.0.1`
(или ваши хосты), а не на имена Docker-сервисов вроде `postgres` или `minio`.

### 4. Установите части приложения

```
composer install
php artisan key:generate
php artisan migrate --seed
php artisan filament:assets
pnpm install
pnpm build
```

Они делают ровно то, что описано в шагах 4.1–4.6 инструкции с Docker:
PHP-библиотеки, секрет приложения, структура базы и стартовые данные (включая
администратора `test@example.com` / `password`), стили панелей,
фронтенд-библиотеки, а также собранные стили и скрипты.

**Должно получиться:** `migrate --seed` заканчивается на `Database seeding
completed successfully`.

### 5. Запустите веб-сервер

Выберите один вариант:

- **Laravel Herd (Windows/macOS):** выполните `herd link` внутри папки один
  раз; после этого Herd постоянно обслуживает сайт по адресу
  `http://<имя-папки>.test`. Убедитесь, что `APP_URL` в `.env` совпадает с
  этим адресом.
- **Встроенный сервер (любая система):** выполните

  ```
  composer dev
  ```

  Это запускает вместе четыре вещи: веб-сервер на `http://127.0.0.1:8000`,
  обработчик очереди, живой просмотр лога и live-reload стилей. Оставьте
  терминал открытым. Убедитесь, что `APP_URL` равен `http://127.0.0.1:8000`.

  Простой `php artisan serve` тоже работает, если нужен только веб-сервер.

**Должно получиться:** открытие `APP_URL` в браузере показывает оформленную
главную страницу.

### 6. Запустите фоновые процессы

Docker запускал их за вас; здесь вы запускаете их сами, каждый в своём
терминале, из папки проекта:

```
php artisan horizon         # обработчик очереди
php artisan schedule:work   # планировщик
php artisan pulse:work      # питатель дашборда производительности
```

Для беглого локального просмотра их можно пропустить. Если пропустите,
учтите:

- Без **`horizon`**: письма-уведомления, импорты/экспорты и агрегация
  статистики фактически не выполняются.
- Без **`schedule:work`**: ночные бэкапы, снятие размещения с истёкшим
  сроком, перегенерация карты сайта и другие задачи по расписанию не
  выполняются.
- Без **`pulse:work`**: дашборд производительности по адресу `/pulse`
  остаётся пустым.

`composer dev` (шаг 5) уже запускает обработчик очереди, поэтому при его
использовании отдельно нужны только `schedule:work` и `pulse:work`.

## Как понять, что всё заработало

Пройдите [`first-run-and-daily-tasks.md`](first-run-and-daily-tasks.md).
Коротко: `APP_URL` + `/up` возвращает `200`; `APP_URL/en` открывается и
оформлен; `APP_URL/portal-admin` показывает страницу входа; можно войти с
`test@example.com` / `password`.

## Обновление до нового кода позже

```
git pull
composer install
php artisan migrate
php artisan filament:assets
pnpm install
pnpm build
php artisan config:clear && php artisan cache:clear
```

Затем перезапустите `composer dev` (или сайт Herd) и фоновые процессы.

## Если что-то не работает

- **`php -v` не 8.5** → [`troubleshooting.md`](troubleshooting.md).
- **Сайт перенаправляет туда, что не отвечает, или стили/ссылки указывают на
  неверный адрес** → `APP_URL` в `.env` не совпадает с адресом, который вы
  открываете. Исправьте, затем `php artisan config:clear` и
  `php artisan cache:clear`.
- **«could not connect» / «connection refused» при запуске** → PostgreSQL или
  Redis не запущен, либо `DB_*` / `REDIS_*` в `.env` не совпадают с тем, где
  они реально слушают.
- **`migrate` падает с упоминанием `postgis`, `pg_trgm` или `unaccent`** →
  шаг 1 пропущен или выполнен не для той базы.
- **Панели отображаются как текст без стилей** → снова выполните
  `php artisan filament:assets`.
- **Что-то ещё** → [`troubleshooting.md`](troubleshooting.md).
